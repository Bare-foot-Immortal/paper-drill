## 一、图标不显示

### 1.1 现象

双击 `PaperDrill.exe` 后，窗口标题栏左上角与任务栏显示的是系统默认空白图标，
而不是 `assets/PaperDrill.ico` 里的「练」字青绿图标。exe 文件本身在资源管理器里有图标。

### 1.2 根因（两处叠加）

1. **源码运行时找不到图标**：`ui/application.py::app_icon_path()` 的路径少算了一级目录——
   候选路径是 `src/assets/PaperDrill.ico` 与 `src/paperdrill/assets/PaperDrill.ico`，
   而图标实际在仓库根目录 `assets/PaperDrill.ico`，因此返回空串，`QApplication.setWindowIcon()`
   从未执行。
2. **打包后图标资源不存在**：`build_exe.ps1` 只用 `--icon` 把 ico 设为 **exe 文件图标**，
   没有 `--add-data` 把它放进 PyInstaller 运行时解包目录（`_MEIPASS`）。
   即使路径算对，单文件 exe 内也找不到 `assets/PaperDrill.ico`，窗口图标仍为空。

### 1.3 修复

| 位置 | 修改 |
|---|---|
| `ui/application.py` | `app_icon_path()` 修正为：`_MEIPASS/assets` → 仓库根 `assets` → 包内 `assets` → exe 同目录 `assets`；新增 `apply_app_icon(app)` 统一设置并返回实际路径 |
| `ui/application.py` | 新增 Windows `AppUserModelID`（`PaperDrill.App`），让任务栏使用程序图标而不是默认占位图标 |
| `ui/main_window.py` | 创建主窗口时再次显式 `setWindowIcon()`，避免外部创建 QApplication 时丢图标 |
| `build_exe.ps1` | 打包参数增加 `--add-data "<ico>;assets"`，把图标放进运行时资源；`--icon` 仍保留为 exe 文件图标 |
| `assets/PaperDrill.ico` | 纳入版本库（不再由 `.gitignore` 忽略），源码运行无需先生成图标 |
| `ui/selftest.py` | 自检新增 `version` / `icon` 字段：图标文件存在、QApplication 图标非空、主窗口图标非空、版本号一致，任一项失败则 `ok=false` |

### 1.4 验证

* `tests/test_qt_icon.py`（6 项）：图标路径可定位、文件有效、QApplication/主窗口图标非空、
  `packaging/version_info.txt` 与 `__version__` 一致、README/使用说明版本号一致。
* `tests/test_qt_selftest.py` 增加对 `version` 与 `icon` 三个布尔值的断言。
* 打包产物 selftest 的 JSON 中 `icon.file_exists/app_icon_ok/window_icon_ok` 均为 `true`；
  真实窗口截图的标题栏图标已从默认空白变为「练」字图标。

## 二、版本号检查

本次发布把版本号统一到 **1.3.2**，并逐处核对：

| 位置 | 值 |
|---|---|
| `src/paperdrill/__init__.py::__version__` | `1.3.2` |
| `packaging/version_info.txt`（filevers/prodvers/FileVersion/ProductVersion） | `1.3.2.0` |
| `README.md` / `使用说明.md` | `1.3.2` |
| 窗口标题 | `刷题匠 PaperDrill v1.3.2 —— 题库练习与模拟考试` |
| 关于对话框 | 读取 `__version__`，显示 `v1.3.2` |
| exe 文件属性 | `FileVersion/ProductVersion = 1.3.2.0` |
| Qt selftest JSON | `version = 1.3.2` |

`tests/test_qt_icon.py::TestVersionMetadata` 会在版本号漏改时直接失败，
避免再次出现「界面 1.3.2、exe 仍是 1.3.1」这类不一致。
