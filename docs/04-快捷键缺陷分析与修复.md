# Enter 快捷键失效 —— 缺陷排查与修复报告

| 项 | 内容 |
|---|---|
| 报告版本 | 1.0 |
| 软件 | 刷题匠 PaperDrill（问题版本 v1.1.0 → 修复版本 **v1.1.1**） |
| 用户反馈 | "快捷键 Enter 不生效" |
| 排查日期 | 2026-10-01 |
| 排查结论 | **确认为软件缺陷，共定位 5 处问题（3 处直接相关 + 2 处连带发现），已全部修复并回归验证** |

---

## 1. 排查方法

不靠猜测，直接在真实 Tk 事件分发链上复现。核心手段：

```python
widget.event_generate("<Return>", when="now")   # 投递真实按键事件
```

Tk 的按键派发顺序是 `widget → class → toplevel → all` 四个 bind tag；把事件投递到某个控件，
与"键盘焦点落在该控件时按下 Enter"的派发路径一致。据此逐场景探测：

| 探测项 | 方法 |
|---|---|
| 绑定是否存在 | `widget.bind(...)` / `bind_all(...)` 的返回值 |
| 各控件类是否吞掉按键 | `tk bind <Class> <Return>` 查类绑定 |
| 场景是否生效 | 投递事件后检查"处理器是否被调用 / 题号是否前进" |
| 能否合成按键 | `event generate . <KP_Enter>` 是否报 `no keycode for keysym` |

排查脚本（已固化到项目）：`_diag/enter_diag.py`、`_diag/typing_diag.py`、`_diag/class_bindings.py`、
`_diag/focus_debug.py`、`_diag/isolation_debug.py`。

## 3. 定位到的缺陷

### BUG-1（直接）模拟考试页 Enter 完全无响应

- **现象**：在「模拟考试」页按 Enter，题号不前进，什么都不发生。
- **根因**：`_on_enter()` 首行 `if self.notebook.index("current") != 0: return`——
  该分支是 v1.1 加入标签页时留下的，只处理了练习页，**考试页被直接 return 掉**。
- **影响**：考试作答时最常用的"Enter 下一题"完全失效，与用户反馈完全吻合。
- **修复**：拆分为 `_practice_enter()` / `_exam_enter()`；考试页 Enter = 下一题，
  到最后一题则提示"按 F9 交卷"，不再越界。

### BUG-2（直接）焦点在输入框时 Enter 无响应，且敲数字/字母会误改答案

- **现象 A**：刚在「蓝图题量/分值」Spinbox 里输过数字，之后按 Enter 没反应。
- **现象 B**：在输入框里敲 `1`/`2`，练习页的选项会被选中或勾选（严重的误操作）。
- **根因**：`<Key>` 与 `<Return>` 绑定未排除输入类控件。`Entry/Spinbox/Combobox` 的类绑定是
  `# nothing`（不 break，事件继续冒泡到窗口绑定），因此窗口绑定把"打字"当成了"选答案"；
  Enter 则在练习页走到"未作答"分支而不做任何事。
- **修复**：新增守卫 `_shortcut_allowed(event)`，同时排除两类事件：
  1. 事件来自**其它窗口**（弹窗、错题本、使用说明等 Toplevel）——避免误触发主窗口；
  2. 事件发生在**输入类控件**上（`TEntry/TSpinbox/Entry/Spinbox/Text/TCombobox`）——
     打字就是打字，不是选答案。

### BUG-3（直接）小键盘回车 `<KP_Enter>` 未绑定

- **现象**：按小键盘上的 Enter 完全无反应。
- **根因**：只绑定了 `<Return>`。
- **平台事实（实测）**：本机 Windows + Tk 9.0.4 下，`event generate <KP_Enter>` 报
  `no keycode for keysym "KP_Enter"`，即**当前平台的 keymap 里没有 KP_Enter**，
  两个回车键都由 Tk 报为 `Return`。因此该缺陷在 Windows 上不构成用户的实际故障，
  但在 X11/Linux 等平台会出现。
- **修复**：`<Return>` 与 `<KP_Enter>` **同时绑定**（面向跨平台），并在测试中固化"必须已绑定"。

### BUG-4（连带发现）键盘选完单选题不会立即判定

- **现象**：用 `1~8` 选中单选答案后，选项框显示已选中但**不出判题结果**；
  此时按 Enter 又被告知"请先选择答案"（其实已经选了）。
- **根因**：`_practice_key()` 只 `set()` 变量，没有像鼠标点选那样触发 `_submit()`。
- **修复**：`_practice_key()` 对单选/判断选择后立即 `_submit()`（与鼠标一致）；
  `_practice_enter()` 改为"只要已选择就提交"，容错更稳。

### BUG-5（连带发现）从菜单启动考试不会切到考试页

- **现象**：在练习页时用菜单「模拟考试 → 开始/继续模拟考试」，界面看起来"没反应"。
- **根因**：`_start_exam()` 只切换了考试标签页**内部的视图**，
  没有 `notebook.select(1)`，用户仍停留在练习页。
- **修复**：`_start_exam()` 末尾切到「模拟考试」标签页。

### 健壮性改进（非缺陷但同类风险）

- **全局绑定改为 `bind_all`**：原实现绑在 root 上（toplevel tag），一旦某个控件类绑定返回
  `break` 就会被吞掉。改为 `bind_all` 后，无论焦点在选项、按钮还是题号格上都能生效。
- **对话框关闭后归还焦点**：新增 `_restore_focus()` / `_bind_dialog_focus()`。
  Tk 的焦点窗口若指向已销毁的对话框，后续按键会**无处派发**，表现为"所有快捷键突然失灵"。
  现在所有 Toplevel 关闭时都会把焦点交还主窗口。

## 4. 一并排除的假设（实测无问题）

| 假设 | 结论 | 依据 |
|---|---|---|
| ttk 按钮的类绑定吞掉了 Enter | 不成立 | `bind TButton <Return>` 为空 |
| 经典 Button（题号格）吞掉 Enter | 不成立 | `bind Button <Return>` 为空 |
| 作答后选项被禁用导致按键丢失 | 不成立 | 禁用控件上仍能派发，⑤ 场景实测通过 |
| 多选题 Enter 提交坏了 | 不成立 | ④ 场景实测通过（修复前的失败是测试隔离假象） |
| Windows 上小键盘回车是 KP_Enter | 不成立 | keymap 无该 keysym，两键均为 Return（仍已做兼容绑定） |

**测试环境陷阱（记录备查）**：同一进程内创建第 2 个及以后的 `tk.Tk()` 时，
若窗口处于 `withdraw()` 状态，Tk 没有焦点窗口，`event_generate` 产生的事件会被直接丢弃
（表现为"绑定存在但处理器不被调用"）。这是测试环境的限制，不是产品缺陷。
自动化测试因此改为：把窗口显示出来（缩到 1x1 并置 `-alpha 0`）后再投递事件；
无法合成的按键（KP_Enter）则用事件对象直接驱动处理器。

## 7. 给用户的结论

1. **Enter 不生效确认为软件缺陷**，主因有两个：模拟考试页的 Enter 被代码直接忽略；
   焦点在输入框时 Enter 与数字键被错误处理。
2. 已修复并发布 **v1.1.1**；`Enter` 与 `F9`（交卷）、`←/→`（翻题）、`1~8/A~H`（选答案）
   现在在练习页与考试页都一致可用。
3. 现在无论焦点停在选项、按钮、题号格还是输入框，快捷键行为都是确定的：
   **输入框里打字就是打字，不会被当成选答案**。
4. 若仍然遇到 Enter 无反应，请检查是否按在其它程序窗口上（此时按键不归本软件接收），
   或提供复现步骤以便继续排查。
