## 0. 改造背景与目标

### 0.1 现状

v1.2.4 的界面基于 **tkinter/ttk**（标准库）。它的优点是零额外依赖、打包体积小（约 13 MB），
但也带来三个实测可见的问题：

| 问题 | 具体表现 |
|---|---|
| 视觉陈旧 | 系统原生灰白控件、无圆角、无层次；题卡、选项、状态条视觉权重相同，重点不突出 |
| 交互密度低 | 选项用原生 Radiobutton / Checkbutton 竖排，题量与统计信息挤在一行文字里 |
| 表现力受限 | 无法优雅实现「答对/答错」着色反馈、进度环、成绩环、深色调色板；高 DPI 下字体与间距不统一 |

这些都属于**表现层**问题：判题、组卷、进度、错题本等业务逻辑经过 193 项测试验证，不需要改动。

### 0.2 本次目标

> **在完全不降低既有功能与可靠性的前提下，把界面换成 Qt（PySide6），做出层次清晰、反馈明确、
> 支持深色主题与高 DPI 的现代桌面观感。**

拆解为四条可验收目标：

| 编号 | 目标 | 验收方式 |
|---|---|---|
| G-1 | 业务功能零缺失：FR-1 ～ FR-15 在 Qt 界面全部可用 | 对照 `01-需求规格说明书.md` 逐条走查 + 自动化测试 |
| G-2 | 观感现代化：统一设计令牌（色彩/圆角/间距/字号）、卡片式题面、选项即反馈、状态实时可见 | 截图评审 + 设计令牌断言 |
| G-3 | 交互不退化：快捷键（1~8 / A~H / Enter / ← → / F5 / F9）、输入框守卫、自动下一题全部保留 | Qt 层自动化测试 |
| G-4 | 可打包、可回退：单文件 exe 可产出；PySide6 缺失时自动回退 tkinter 界面，程序仍能启动 | 打包验证 + 回退分支测试 |

### 0.3 明确不做

- **不改动**已通过验证的领域层（`models` / `bank_io` / `store` / `paper` / `practice` / `config`）；
- **不删除** tkinter 界面（`gui.py`）——它保留为回退实现，同时是既有 193 项测试的基线；
- 不新增联网、云同步、账号体系；
- 不做试卷导出（该能力仍归组卷版 PaperForge）。

## 1. 技术选型（FR-16）

| 项 | 选型 | 理由 |
|---|---|---|
| GUI 框架 | **PySide6（Qt 6）**，实际安装 `PySide6-Essentials` | 官方 LGPL 绑定；QtWidgets 足以覆盖本软件全部控件；Essentials 比完整包少 WebEngine/Addons，打包更小 |
| 版本约束 | `PySide6-Essentials >= 6.10, < 7` | 6.10 起声明支持 Python 3.14（本项目使用 3.14）；上限防止跨大版本破坏 |
| 样式方案 | **QSS（Qt 样式表）+ 集中式设计令牌** | 无需外部资源；令牌集中在一处，便于统一调整与暗色主题切换 |
| 图表/环形进度 | 自绘 `QPainter` 控件 | 不引入 matplotlib（体积大），环形进度/成绩环绘制量很小 |
| 表格 | `QTableView` + 自定义 `QAbstractTableModel` | 虚拟化渲染，题库删减对话框上万题也不卡 |
| 打包 | PyInstaller（沿用 `build_exe.ps1`） | 已成熟的单文件链路，只需补 Qt 的 hidden-import 与插件收集 |
| 测试 | 标准库 `unittest` + `QT_QPA_PLATFORM=offscreen` | 与既有测试风格一致，无需额外测试框架；无显示环境也能跑 |

> 备选方案（未采用）：CustomTkinter（仍是 Tk 渲染，观感提升有限）、Web UI + pywebview（引入前端技术栈，
> 打包与进程通信复杂化）。

## 2. 功能需求

### 2.1 结构性需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-16.1 | 左侧主导航 + 右侧工作区布局 | 三个入口：**练习**、**模拟考试**、**题库资料**；当前页高亮 |
| FR-16.2 | 顶栏显示当前题库与核心统计 | 题库名、题数构成、已练/正确率/错题数常驻可见 |
| FR-16.3 | 底部状态栏 | 操作结果、错误与保存失败提示统一在此展示 |
| FR-16.4 | 支持深色 / 浅色 / 跟随系统三种主题 | 切换即时生效，**不重启**；选择持久化到配置文件 |
| FR-16.5 | 高 DPI 缩放 | 启用 Qt 高 DPI 策略；125%/150%/200% 缩放下布局不重叠、不溢出 |
| FR-16.6 | 窗口几何与分割位置持久化 | 关闭再打开保持上次大小、位置与左右栏宽度 |

### 2.2 练习页需求（FR-17，对应既有 FR-1/4/5/6/9/13a）

| 编号 | 需求 |
|---|---|
| FR-17.1 | 范围切换：整个题库 / 只练单选 / 只练多选 / 只练判断（分段控件） |

### 2.5 交互与可访问性需求（FR-20）

| 编号 | 需求 |
|---|---|

## 5. 验收标准

本次改造的验收由四部分组成，全部通过方可发布：

1. **功能走查**：第 2 章逐条对照界面确认（含 FR-18.7 考试中无对错提示这一硬性项）。
2. **自动化测试**：既有 193 项测试全部通过（tkinter 回退链路不受影响）；新增 Qt 层测试覆盖：
   控制器状态机、练习页判定渲染、快捷键与输入框守卫、考试流程与只读、主题切换、回退分支。
3. **无头自检**：`PaperDrill --qt-selftest` 在无人值守环境下跑完
   导入→练习→组卷→考试→交卷→重开恢复→删减→恢复 的完整闭环并输出 JSON 结果。
4. **人工验收**：浅色/深色 × 100%/150% 缩放四组截图评审，检查层次、对齐、对比度与溢出。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Qt 运行库缺失导致启动失败 | 用户打不开软件 | 入口处 `try: import PySide6 except ImportError: 回退 tkinter`，并在状态栏提示 |
| 打包漏收 Qt 插件（platforms/styles） | exe 启动黑屏或报 "could not find platform plugin" | `build_exe.ps1` 显式 `--collect-all PySide6`，产物做启动冒烟测试 |
| exe 体积明显增大 | 分发体积从 13 MB 到 90~100 MB | 采用 Essentials 子集、排除 QtWebEngine/QtQml 未用模块；README 说明体积变化原因 |
| 两套界面行为漂移 | 用户困惑 | tkinter 版冻结不再演进；Qt 版为唯一功能演进主线，回退仅保证"能开、能练" |
| 快捷键与输入框冲突（历史 BUG） | 打字被当成选答案 | 统一 `focusWidget` 守卫，并保留专门的回归测试 |
