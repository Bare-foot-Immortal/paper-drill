## 3. 逐条需求验证

### 需求 1：三种题型
单选题 101、多选题 32、判断题 30 全部正确解析与分类；范围筛选、蓝图、考试三处均按三分类工作。

### 需求 2：题量与各题型占比可自定义
蓝图 20/10/10 实测：

| 卷 | 单选 | 多选 | 判断 | 合计 |
|---|---|---|---|---|
| A～F（6 张，全部一致） | 20 | 10 | 10 | **40** |

界面实时显示"每卷合计 40 题，满分 50 分"；分值（单选 1 / 多选 2 / 判断 1）可改。

### 需求 3：一轮覆盖题库全部题目 + 末卷补题

**（a）真实 52 题库 + 每卷 40 题**：轮长自动算出 **2 张/轮**，覆盖 **52/52**。

```
[蓝图] 每卷 40 题（单选 20、多选 10、判断 10）
[轮长] 覆盖题库全部题目需 2 张/轮（题库：单选 101、多选 32、判断 30）
[生成] 一轮 2 张，题库 52 题已覆盖 52 题（覆盖完整）　随机种子 7
       A卷：40 题（补题 0）  B卷：40 题（补题 0）  C卷：40 题（补题 0）
       D卷：40 题（补题 18） E卷：40 题（补题 20） F卷：40 题（补题 39）
```

- 补题明细符合算法：**D 卷多选 2 新 + 8 补、判断 10 全补 ⇒ 18**；主算法用例单独断言了这 8 题；
- **需求 3 原文示例**（题库 120 题、每卷 40 题 → 3 张一轮且全部出现过）已作为独立用例 `test_requirement_example_120_questions` 验证通过；
- 手动把轮长设为 3 时：仍生成每卷 40 题，但 `coverage_ok=False`、未覆盖题数 >0，并给出"无法覆盖"告警。

### 需求 4：多选题「定」固定顺序
示例题库「（定）」题（`A.3～4 B.4～5 C.垂直 D.平行`，答案 `BC（定）`）验证：

| 场景 | 结果 |
|---|---|
| 练习（打乱开启，50 次随机） | 选项顺序与题库一致，答案保持 `BC` |
| 组卷出卷（进入试卷） | 题目保持 `fixed_order`，答案 `BC` 不变 |
| 模拟考试（打乱开启） | `shuffled=False`，选项文本与题库一致 |

### 需求 5：单选、多选分别选择是否打乱

| 场景 | 结果 |
|---|---|
| 只关单选打乱 | 单选题选项 == 题库原序；多选题仍被打乱 |
| 只关多选打乱 | 多选题选项 == 题库原序；单选题仍被打乱 |

| 定题 | 任何开关下都不打乱 |

## 5. 缺陷与修复记录

| 编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| D-01 | 提交答案报 `AttributeError: apply_answer` | 引擎调用的方法只存在于 `BankProgress` | `ProgressStore` 增加代理方法；练习单题即时落盘，考试批量一次落盘 |
| D-02 | 判断题没有可点选项 | 题库中判断题无选项列 | 渲染层统一为「A. 正确 / B. 错误」，判题兼容字母集合与 bool |
| D-03 | CLI `--mode wrong` 不生效 | 恢复会话时把模式一起覆盖 | `restore_position(adopt_mode=False)` 只恢复位置 |
| D-04 | `--list-progress` 未用指定进度目录 | 模块顶部导入绑定了原函数 | 改为运行时通过模块属性查找 |
| D-05 | CLI 不认 `--bank` | 只定义了位置参数 | 增加 `--bank` 别名 |
| D-06 | 自检中"错答"统计与预期不符（未答 11 / 错 9） | 全对型多选题（如答案是 ABCD）没有可选的"错误选项"，取不到错答导致变成未答 | 自检改为选其正确选项的**子集**（少选）以构造错答；评分口径同步在用例中断言 |
| D-07 | 卷级"补题数"断言写错（期望 8，实际 18） | 8 是"多选"单题型的补题数，卷级补题数是三题型之和 | 修正断言为 `[0,0,0,18,20,39]`，并把单题型补题断言放到 `TestPaperRound` |
| D-08 | exe 的 CLI 输出经管道捕获为乱码/丢失 | GUI 版 exe 通过 `AttachConsole` 直接写控制台句柄，管道捕获不可靠 | 新增 `--log FILE` 把输出同时落盘（UTF-8），批量使用也更实用 |
| D-09 | 成绩页明细区滚动条与表格重叠 | 滚动条与 Treeview 同格布局 | 用子框架包裹 Treeview + 滚动条 |
| **D-10** | **用户反馈"Enter 快捷键不生效"：模拟考试页按 Enter 无任何反应** | `_on_enter()` 首行 `if notebook.index("current") != 0: return`，考试页分支被直接跳过 | 拆分 `_practice_enter` / `_exam_enter`；考试页 Enter = 下一题，末题提示按 F9 交卷 |
| **D-11** | **焦点在输入框（蓝图题量/分值）时：Enter 无反应，且敲数字/字母会误选练习答案** | 快捷键绑定未排除输入类控件；`Entry/Spinbox` 的类绑定不 break，事件冒泡到窗口绑定后被当成"选答案" | 新增 `_shortcut_allowed(event)` 守卫：排除其它窗口的事件与非本窗口输入控件上的事件 |
| **D-12** | 小键盘回车完全无反应 | 只绑定了 `<Return>`，未绑定 `<KP_Enter>` | 同时绑定 `<Return>` 与 `<KP_Enter>`（实测 Windows 的 Tk keymap 无 KP_Enter，两键均报 Return；绑定为跨平台兼容） |
| **D-13** | 键盘选中单选后不立即判定，随后按 Enter 提示"请先选择答案" | `_practice_key()` 只设置变量，未像鼠标点选那样触发提交 | 单选/判断按键选择后立即判题；Enter 改为"已选择即提交" |
| **D-14** | 在练习页用菜单启动考试时界面"没反应" | `_start_exam()` 只切换考试页内部视图，未 `notebook.select(1)` | 启动考试时自动切到「模拟考试」标签页 |
| **D-15** | 全局绑定在 root 上（toplevel tag），可能被控件类绑定吞掉；对话框关闭后焦点可能丢失导致所有快捷键失灵 | 绑定层级不够靠后；Tk 焦点窗口指向已销毁控件 | 改用 `bind_all`；新增 `_restore_focus` / `_bind_dialog_focus`，4 个对话框与关键 messagebox 关闭后归还焦点 |
| **D-16** | **用户反馈"点重新开始本轮后不能正常答题"** | `_render_current()` 对已作答题目调用 `_show_answered(replay=True)`，而该函数职责是"判题后锁定本题"，于是回看被实现成锁死 | 新增 `_show_replay()`：回看状态**保持可作答**，只提示上次结果、不公布答案 |
| **D-17** | **「错题重练」模式完全不可用（错题必然已作答 → 全部被锁定并剧透答案）** | 同 D-16 | 同 D-16 |

> 自动化测试据此改为显示窗口（1x1 + `-alpha 0`）后再投递事件。

## 6. 已知限制

1. 多选题不设部分分（少选/多选/错选均判错）；未答题按错误计分（成绩页单列"未答"）；
2. 题干或选项被修改过的题目视为新题，进度从零开始；
3. 本版**不导出/不打印试卷**（导出由组卷版 PaperForge 承担）；
4. 换机器携带进度需自行拷贝 `%APPDATA%\PaperDrill\progress\` 目录；
5. 界面自动化采用无头自检（真实 Tk 对象 + 全流程调用），未做像素级 UI 自动化。

## 6. Excel / CSV 排布兼容性（v1.2.1 / v1.1.1 起放宽）

**不必照着示例逐列对齐。** 软件按「列名」理解表格，识别不到列名时才按列位置兜底。

### 6.1 这些都支持

| 情况 | 说明 |
|---|---|
| 首行是题库标题 | 列头从第 2 行开始也能找到（**前 20 行**内均可） |
| 标题与列头之间有空行 | 支持 |
| 列头写在第 15 行 | 支持（旧版只扫前 5 行） |
| 列的顺序与示例不同 | 答案/解析放最前、题干放最后都可以 |
| 选项列乱的 | `选项C` 排在 `选项A` 前面也能正确归位 |
| 「题型」列放在最后一列 | 支持 |
| 多个工作表 | 自动挑「能识别列头 / 行数最多」的那张表（说明页会被跳过） |
| 完全没有列头 | 按标准列位置解析（题型/题干/选项A–H/解析/答案） |
| 列头写法不同 | `题目类型`/`题干`/`题干内容`/`A选项`/`选项 B`/`选项1`/`optionA`/`正确答案`/`答案解析` 等均识别 |
| 列头带空格/换行/全角 | 支持（自动归一化） |
| 题型写成 `单选题（每题1分）` | 支持（含关键字即可） |
| 选项全部挤在一列 | `选项` 列内容写 `A.甲 B.乙 C.丙 D.丁` → 自动拆开 |
| 没有「题型」列 | 由答案推断：多字母→多选、`√×对错`→判断、单字母→单选 |

### 6.2 仍需人工整理的情况

| 情况 | 建议 |
|---|---|
| 无列头且列顺序不符合标准布局 | 加一行列头最稳妥 |
| 选择题没有选项列 | 无法作答，软件会报「单选题缺少选项（只识别到 0 个选项列）」 |
| 「题型」列写了无法识别的值（如 `选择题`） | 软件会明确报「题型无法识别：'选择题'」，不会猜测 |
| 选项中间有空列 | 报「选项不连续（中间存在空列）」 |
| 题干合并了多行/单元格 | 建议每行一题、题干在一个单元格内 |

所有无法导入的行都会以「行号 + 原因 + 题干片段」列出，按提示修补即可。
