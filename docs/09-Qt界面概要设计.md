## 1. 设计目标与约束

1. **业务层零改动**：`models` / `bank_io` / `store` / `paper` / `practice` / `config` 一行不改。
   UI 只通过它们的公开方法读写数据，因此既有的 131 项领域测试天然继续有效。
2. **表现层可无头测试**：所有界面逻辑不依赖真实显示，`QT_QPA_PLATFORM=offscreen` 下可跑完整流程。
3. **状态集中在控制器**：界面控件只负责"显示状态、上报用户意图"，不各自持有业务状态，
   避免 v1.2 中"按钮禁用状态残留""交卷后卷面仍可点"这类问题的再次出现。
4. **可回退**：PySide6 导入失败时退回 tkinter，功能降级但不崩溃。

约束：不引入 Web 技术栈；不引入 matplotlib/pandas 等重依赖；不改变任何数据文件格式。

## 2. 分层架构

```
┌──────────────────────────────────────────────────────────────────────┐
│  表现层（新增）                                                        │
│  ┌────────────────┐ ┌────────────────┐ ┌────────────────┐            │
│  │ PracticePage   │ │ ExamPage       │ │ LibraryPage    │            │
│  │ 题卡/选项/反馈  │ │ 配置/作答/成绩 │ │ 题库资料/最近  │            │
│  └───────┬────────┘ └───────┬────────┘ └───────┬────────┘            │
│          │ 读取状态/发意图    │                  │                     │
│  ┌───────▼──────────────────▼──────────────────▼────────┐            │
│  │  MainWindow（导航 / 菜单 / 快捷键 / 状态栏）           │            │
│  └───────────────────────────┬───────────────────────────┘            │
│  ┌───────────────────────────▼───────────────────────────┐            │
│  │  PaperDrillController（QObject + 信号，UI 无关）       │            │
│  │  状态机：无题库 → 练习中 ⇄ 考试配置 → 考试中 → 成绩     │            │
│  └───────────────────────────┬───────────────────────────┘            │
└──────────────────────────────┼────────────────────────────────────────┘
                               │ 只调用公开 API
┌──────────────────────────────▼────────────────────────────────────────┐
│  领域层（不变）                                                        │
│  practice.PracticeSession / ExamSession                                │
│  paper.generate_round / min_round_length                              │
│  store.ProgressStore / BankLibrary / QRecord                          │
│  bank_io.load_bank / bank_stats                                        │
│  config.AppSettings                                                    │
└───────────────────────────────────────────────────────────────────────┘
```

**数据流（单向）**：

```
用户操作 → 控件发出意图（clicked / key / valueChanged）
        → Controller 调用领域层方法
        → Controller 发出信号（state_changed / practice_changed / exam_changed …）
        → 页面按当前状态整段重绘（不维护自己的副本）
```

"整段重绘"是本设计的关键取舍：题目卡片、选项、反馈每次都按权威状态重建。
代价是一次重建的开销（微秒级），收益是**不可能出现残留状态**——这正是 v1.2 两处已修缺陷的根因。

## 4. 控制器设计（`ui/controller.py`）

### 4.1 状态模型

```python
@dataclass
class UiState:
    bank: BankLoadResult | None      # 题库原文件全量题目
    store: ProgressStore | None      # 当前题库进度
    session: PracticeSession | None  # 练习会话
    exam: ExamSession | None         # 进行中的考试
    exam_result: ExamResult | None   # 最近一次交卷成绩
    round: PaperRound | None         # 最近生成的一轮试卷
    round_view: str = "config"       # config | taking | result
    exam_index: int = 0              # 考试当前题号（0 基）
    answered: bool = False           # 当前题是否已判定（练习）
    feedback: str = ""               # 练习反馈正文
    feedback_kind: str = ""          # correct | wrong | reveal | idle
    analysis_text: str = ""
    save_error: str = ""             # 进度落盘失败原因
```

### 4.2 信号

| 信号 | 触发时机 | 订阅方 |
|---|---|---|
| `state_changed()` | 任何状态变化（总信号） | 顶栏、状态栏 |
| `practice_changed()` | 练习题目/选项/反馈变化 | `PracticePage` |
| `exam_changed()` | 考试视图或当前题变化 | `ExamPage` / `ExamRunPage` |
| `paper_changed()` | 一轮试卷生成或作废 | `ExamPage` 配置视图 |
| `stats_changed()` | 统计口径变化 | 顶栏、练习页底部 |
| `status_message(str)` | 需要展示给用户的一句话 | 状态栏 |
| `library_changed()` | 题库库增删 | `LibraryPage` |

### 4.3 关键方法

```python
load_bank(path) -> bool          # 载入题库 → 恢复会话 → 刷新统计
reload_bank()                    # 重新解析当前题库
```

### 4.4 状态迁移

```
        ┌──────────────┐  load_bank   ┌───────────────┐
        │ 无题库（空态）│ ───────────► │  练习中        │
        └──────────────┘              └───┬───────┬───┘
             ▲                            │       │ generate_round
             │ 题库解析失败                │       ▼
             └────────────────────────────┤  ┌──────────────┐
                                          │  │ 考试配置      │
                                          │  └──┬───────────┘
                                          │     │ start_exam
                                          │     ▼
                                          │  ┌──────────────┐
                                          │  │ 考试中（只读?）│
                                          │  └──┬───────────┘
                                          │     │ submit_exam
                                          │     ▼
                                          │  ┌──────────────┐
                                          └─►│ 成绩（只读卷面）│
                                             └──────────────┘
```

**不变量**

- `exam.submitted is True` ⇒ 所有作答入口（`exam_set` / `exam_toggle` / `exam_clear`）必须直接返回；
- 删减题目后 ⇒ `round` 作废（旧卷基于旧题目集），必须重新生成；
- 交卷后 ⇒ 练习队列按新的错题/进度重建，但**练习位置必须保持不变**（v1.2 缺陷回归点）；
- `store.last_save_error` 非空 ⇒ 必须通过 `status_message` 暴露，不得吞掉。

## 6. 关键实现细节

### 6.1 快捷键分发（FR-20.1 ～ 20.3）

```python
def _shortcut_target_ok(self) -> bool:
    w = QApplication.focusWidget()
    # 输入类控件（QLineEdit/QAbstractSpinBox/QComboBox/QTextEdit）获得焦点时不劫持
    return not isinstance(w, (QLineEdit, QAbstractSpinBox, QComboBox, QTextEdit, QPlainTextEdit))
```

- 用 `QShortcut`（`WidgetWithChildrenShortcut`）绑定在 `QMainWindow` 上 → 对话框不继承，天然满足 FR-20.3；
- `1~8/A~H` 用 `QShortcut(QKeySequence(str(n)))`，`Enter` 绑定 `Return` 与 `Enter`（小键盘）；
- `←/→` 绑定 `QShortcut`，在练习页翻题、在考试页翻题。

### 6.2 自动下一题（FR-17.3）

用 `QTimer.singleShot(settings.auto_next_delay_ms)`；每次渲染新题前 `auto_next_timer.stop()`，
避免"上一题的定时器把下一题跳掉"（v1.2 已修过同类问题，设计上必须显式取消）。

### 6.3 主题切换（FR-16.4）

`ThemeManager.apply(qapp, mode)`：选择令牌表 → 生成 QSS 字符串 → `qapp.setStyleSheet(...)` →
同时更新 `QPalette`（保证原生绘制部分——如滚动条箭头、工具提示——也跟随主题）。
切换后发 `theme_changed` 让自绘控件（`ProgressRing`）重绘。

### 6.4 高 DPI（FR-16.5）

Qt 6 默认启用高 DPI 缩放，无需旧式 `AA_EnableHighDpiScaling`。
额外处理：`QApplication.setHighDpiScaleFactorRoundingPolicy(PassThrough)`；
所有尺寸用逻辑像素；图标用 `QIcon` 多尺寸或矢量绘制。

### 6.5 回退策略（NFR-6）

```python
# paperdrill/__main__.py（改动）
try:
    from .qt_app import run as run_gui, available as qt_available
except Exception:
    qt_available = False
if qt_available:
    return run_gui(path)
from .gui import run as run_tk
return run_tk(path)
```

`qt_app.available()` 内部 `import PySide6` 并尝试创建 `QApplication`；
任何异常（含无显示环境）都返回 False，把用户交给 tkinter 版本，并在终端打印一行原因。

### 6.6 进度与设置兼容（NFR-5）

- 进度文件格式不动；
- `AppSettings` 新增 `theme: str = "system"`、`last_page: str = "practice"`、`qt_window_state: str = ""`；
- `AppSettings.load()` 已有"逐字段按默认值类型转换"的容错逻辑，新字段在旧文件缺失时自动取默认值。

## 9. 与 tkinter 版的关系

| 维度 | tkinter 版（`gui.py`） | Qt 版（`ui/`） |
|---|---|---|
| 状态 | **冻结**：只修安全/数据缺陷，不加功能 | 功能演进主线 |
| 角色 | PySide6 不可用时的回退；既有 193 项测试的基线 | 默认启动的界面 |
| 数据 | 与 Qt 版共用同一份进度与配置 | 同左 |

两版不会同时运行；用户只会看到其中一个界面。
